# Olang v0.17 Feature Checklist - Simple Multi-File Projects

## Release Theme: **Effortless Code Organization**

**v0.17 Vision**: Enable developers to naturally organize code across multiple files with zero boilerplate, automatic discovery, and intuitive sharing - making multi-file development as simple as single-file programming.

## Core Philosophy: **Zero Configuration, Maximum Intuition**

- **Files are modules** - Every `.ol` file is automatically a module
- **Folders are namespaces** - Directory structure creates natural organization  
- **Explicit sharing** - Only functions marked `share` are available to other files
- **Direct imports** - Simple `use` statements bring functions into scope
- **Automatic discovery** - No manifests, declarations, or complex resolution rules

## Core Multi-File Features

### Feature 1: Automatic File-Based Modules
**Status**: ✅ **COMPLETED**  
**Priority**: 🔴 Critical

**Description**: Every `.ol` file automatically becomes a module with zero configuration required.

**How It Works**:
- **Every file is a module** - No declarations needed
- **Filename is the module name** - `math_utils.ol` becomes module `math_utils`
- **Folder structure creates hierarchy** - `utils/string.ol` becomes `utils.string`
- **Everything is private by default** - Clean encapsulation

**Example**:
```olang
// math_utils.ol
fn calculate_area(radius: Float) = PI * radius * radius  // private by default

share fn area_circle(radius: Float) = calculate_area(radius)  // available to other files
share fn area_square(side: Float) = side * side

// main.ol  
use math_utils { area_circle, area_square }

fn main() = {
    println("Circle area: " + area_circle(5.0))
    println("Square area: " + area_square(4.0))
}
```

### Feature 2: Simple Share/Use System
**Status**: ✅ **COMPLETED**  
**Priority**: 🔴 Critical

**Description**: Minimal syntax for sharing functions between files - just `share` and `use`.

**Syntax**:
```olang
// Sharing functions (in any file)
share fn public_function() = "available to import"
share let PUBLIC_CONSTANT = 42
share type UserData = { id: Int, name: String }

// Using functions (in any file)
use other_file { public_function, PUBLIC_CONSTANT }
use utils.helpers { greet, validate }
use math_utils { area_circle }
```

**Grammar Changes**:
```pest
// Simple sharing
share_decl = { "share" ~ (function_decl | let_decl | type_decl) }

// Simple usage
use_decl = { "use" ~ use_path ~ "{" ~ use_list ~ "}" }
use_path = { identifier ~ ("." ~ identifier)* }
use_list = { identifier ~ ("," ~ identifier)* }
```

### Feature 4: Dependency-Free Discovery
**Status**: ✅ **COMPLETED**  
**Priority**: 🔴 Critical

**Description**: Automatically discover and load files without manifests, config files, or complex resolution rules.

**Discovery Rules**:
1. **Relative to current file** - `use sibling_file { function }`
2. **Relative to project root** - `use utils.helpers { function }`
3. **Standard library** - `use std.io { println }` (built-in)
4. **Current directory first** - Always check same folder first

**Algorithm**:
```rust
fn discover_module(use_path: &str, current_file: &Path) -> Result<PathBuf, Error> {
    // 1. Check same directory
    if let Some(path) = check_same_directory(use_path, current_file) {
        return Ok(path);
    }
    
    // 2. Check relative to project root
    if let Some(path) = check_project_root(use_path) {
        return Ok(path);
    }
    
    // 3. Check standard library
    if let Some(path) = check_stdlib(use_path) {
        return Ok(path);
    }
    
    Err(Error::ModuleNotFound(use_path.to_string()))
}
```

### Feature 6: Transitive Sharing
**Status**: ✅ **COMPLETED**  
**Priority**: 🟡 High

**Description**: Allow files to share items from other files they use.

**Example**:
```olang
// base_utils.ol
share fn helper() = "base helper"

// extended_utils.ol
use base_utils { helper }
share use base_utils { helper }  // Re-share helper
share fn extended_helper() = helper() + " extended"

// main.ol
use extended_utils { helper, extended_helper }  // Get both functions
```

**Implementation Details**:
- **Syntax Support**: Added `share use module { items }` syntax to grammar and parser
- **Transitive Exports**: Modules can re-export functions from other modules they import
- **Dependency Chains**: Support for multi-level chains (A → B → C → main)
- **Conflict Avoidance**: System handles naming conflicts by requiring unique names
- **Stack Overflow Detection**: Circular dependencies cause stack overflow (future enhancement: proper detection)

```rust
fn detect_circular_references(files: &[File]) -> Result<(), CircularReferenceError> {
    let mut visiting = HashSet::new();
    let mut visited = HashSet::new();
    
    for file in files {
        if !visited.contains(&file.path) {
            if has_circular_reference(file, &files, &mut visiting, &mut visited) {
                return Err(CircularReferenceError::new(&file.path));
            }
        }
    }
    Ok(())
}
```

## Migration Guide

### From v0.16 to v0.17
1. **Zero breaking changes** - All single-file projects continue to work exactly as before
2. **Gradual adoption** - Add multi-file support when needed
3. **Simple migration** - Just add `share` to functions you want to export
4. **No configuration** - No manifests or complex setup required

### Example Migration
```olang
// Before (v0.16) - Single file approach
fn calculate_area(radius: Float) = PI * radius * radius

fn main() = {
    println("Area: " + calculate_area(5.0))
}

// After (v0.17) - Multi-file approach

share fn calculate_area(radius: Float) = PI * radius * radius
```
